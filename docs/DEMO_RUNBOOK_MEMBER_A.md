## 一、今晚准备

在仓库根目录（含 package.json）打开 PowerShell，使用 Node.js 24.14.0–24.x：

```powershell
npm ci
npm run check
npm run demo:prepare -- --profile ".\runtime\demo-2026-09-29"
$env:CARELINK_PROFILE_PATH = (Resolve-Path ".\runtime\demo-2026-09-29").Path
npm start
```

准备工具只创建新演示资料。若提示目标非空，继续使用该目录，或者换新目录名；不要删除日常数据来解决。日期相对于执行准备命令的当天生成，明早希望刷新日期就准备另一份新目录。正常退出后再次启动只需设置 CARELINK_PROFILE_PATH 并运行 npm start。

不要设置 CARELINK_TEST_MODE，否则自动化测试模式会隐藏窗口。未设置 CARELINK_PROFILE_PATH 时，软件使用日常资料目录，而不是新准备的演示库。

先完成一次下述彩排。确认可用后，退出 CareLink 并备份：

```powershell
npm run profile:backup -- --profile ".\runtime\demo-2026-09-29" --output ".\runtime\backups\demo-ready"
npm run profile:verify -- --backup ".\runtime\backups\demo-ready"
```

已存在的备份不会被覆盖，重新备份需换名字。演示需要的源码、依赖、整个 release/win-unpacked 目录（若打包）、资料和备份应保存在本机。旧 GitHub v0.2.0 安装程序不含本次修改。

## 五、出现问题时

- 登录失败：先确认所用资料目录、账号和密码；已有库可能改过密码。不要切到另一份空资料却误认为保存丢失。
- 提醒没有到达：确认时间、当前患者权限、任务状态、软件仍开着；最多自动尝试三次。超过次数可查看失败状态及审计后手动重试。未支持的模板会失败，不会显示虚假送达。
- 会诊打不开：确认当前医生是参会人，任务未结束且未到授权截止；一般邀请有效至预约开始后 4 小时，提前完成会立即撤权。
- 备份提示目录被占用：正常退出 CareLink 再执行，不绕过资料锁。
- 新版本数据库不适配旧代码：使用匹配版本和独立备份，不手工删除迁移记录。

恢复到新目录：

```powershell
npm run profile:restore -- --backup ".\runtime\backups\demo-ready" --target ".\runtime\demo-restored"
$env:CARELINK_PROFILE_PATH = (Resolve-Path ".\runtime\demo-restored").Path
npm start
```

恢复后重新登录，核对资料、患者、审计和已有社区附件。原演示目录及备份都保留。回到日常资料只需退出软件后执行 Remove-Item Env:CARELINK_PROFILE_PATH，再启动；这只取消环境变量，不删除文件。
