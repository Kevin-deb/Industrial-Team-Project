# E 模块富媒体内容与健康趋势图设计

日期：2026-09-13  
状态：设计已口头确认，等待用户审阅本文后进入实施计划  
范围：仅 E 模块的同行社区富媒体内容、健康观测趋势图、公开契约、追加迁移、缓存与测试

## 1. 目标

本次在现有 E 模块本地实现上增加两项独立能力：

1. 帖子、回复和同行私信支持文字、Emoji、图片、录音、已有音频文件和脱敏医学数据卡。
2. 健康观测在保留记录表的同时，增加带完整数字摘要和年龄参考区间的趋势图。

两项能力共享现有 CareLink 视觉语言和局部异步刷新机制，但数据、服务和界面组件彼此独立。所有数据继续只保存在本机，不提交、不推送、不打包。

## 2. 明确边界

- 不把患者、病历、医嘱、问诊或会诊对象附加到社区内容。
- 社区医学数据卡只能保存用户手工录入并确认脱敏的结构化数值，不保存患者 ID、姓名、联系方式或其他身份标识。
- 只为未来 B 板块预留脱敏、只读的数据提供端口，不实现 B 的患者数据选择器或业务逻辑。
- 趋势图只显示数据变化和带来源的演示参考区间，不自动诊断、分级、给药或生成治疗建议。
- 不改变 A 负责的全局字体缩放、身份权限、审计中心和导航业务。
- 不把图片或音频编码为 Base64 放进普通 JSON 请求或 SQLite 正文字段。

## 3. 交付拆分与顺序

采用两个可独立验收的纵向切片：

1. 健康趋势图：契约、参考区间端口、趋势服务、API、查询缓存、界面与测试。
2. 社区富媒体：内容块契约、文件存储端口、追加迁移、上传与读取 API、统一编辑器、三个使用场景与测试。

每个切片都先完成服务和契约测试，再连接 React 界面。前端数字必须来自实际 API，不维护另一套演示数组。

## 4. 社区统一混合内容模型

### 4.1 兼容原则

现有 `social_posts.body`、`social_comments.body` 和 `social_direct_messages.body` 保留，继续作为每条内容的文字正文。Emoji 直接作为 Unicode 字符保存在正文中。

新增按顺序排列的附加内容块。第一版内容块只包含：

- `image`：引用一个图片附件。
- `audio`：引用一段直接录音或一个上传音频。
- `medical-metric-card`：保存一张脱敏医学数据卡。

正文统一显示在内容块之前。第一版不实现任意图文穿插、富文本排版、视频、文档、患者对象或病历附件。

旧记录没有内容块时按原来的纯文字方式展示，无需回填或重写历史数据。

### 4.2 契约

公共契约增加以下概念：

- `SocialContentBlock`：`id`、`kind`、`order` 和对应内容。
- `SocialAttachment`：`id`、`kind`、`mediaType`、`byteSize`、图片尺寸或音频时长、读取 URL。
- `MedicalMetricCard`：`schemaVersion`、`sourceType`、`measuredAt`、`metrics`、`sourceLabel`、`note`、`deidentificationConfirmed`。
- `MedicalMetricItem`：`metricCode`、`displayName`、`value`、`unit`。

医学数据卡一次最多包含四个同次测量指标。初版允许收缩压、舒张压、心率和血糖，也允许以稳定代码扩展其他指标。`sourceType` 初版只写 `manual`，保留 `provider` 枚举供以后接入 B 的脱敏只读适配器。

`CreatePostInput`、`CreateCommentInput` 和 `CreateMessageInput` 增加可选的 `contentBlocks`。省略或传空数组时保持现有行为。

### 4.3 数据库

使用新的追加迁移，不修改已经执行的迁移。

新增 `social_attachments`：

- 附件 ID、创建者身份、种类、媒体类型、存储键、字节数。
- 图片宽高或音频时长。
- `temporary` / `attached` 状态、创建时间。
- 不保存可被客户端控制的绝对文件路径。

新增 `social_content_blocks`：

- 块 ID、所属实体类型、所属实体 ID、显示顺序、块类型。
- 附件 ID 或医学数据卡 JSON，两者按块类型二选一。
- 内容结构版本和创建时间。

实体类型仅允许 `post`、`comment`、`message`。外键和服务校验防止一个附件被其他用户认领或重复关联。

### 4.4 文件存储

增加 `AttachmentStoragePort`。组合根负责提供应用可写目录，API 和业务服务不写死 macOS 或 Windows 路径。测试使用临时目录实现。

文件名使用服务端生成的不可猜测存储键；原始文件名仅用于必要的界面展示，不参与路径拼接。媒体读取必须通过附件 ID 和受控路由，不允许客户端传本地路径。

允许格式与限制：

- 图片：JPEG、PNG、WebP；单张不超过 5 MiB；一条内容最多 4 张。
- 音频：MP3、M4A/AAC、WAV、WebM/Opus、Ogg/Opus；不超过 10 MiB且最长 3 分钟；一条内容最多 1 段。
- 医学数据卡：一条内容最多 2 张。

服务端校验声明媒体类型、文件特征、实际大小和可读取的音频时长。SVG 不作为图片上传格式，避免脚本型内容进入预览。

### 4.5 上传与认领流程

1. 用户在编辑器中选择文件或完成录音。
2. 客户端通过独立 multipart 路由上传媒体，显示单项进度。
3. 服务端将文件写入临时区并创建 `temporary` 附件记录。
4. 客户端只在帖子、回复或私信 DTO 中传附件 ID 和内容块顺序。
5. 创建业务实体时，服务在同一数据库事务内校验并将附件标记为 `attached`。
6. 业务创建失败时保留编辑器和临时附件，用户可重试。
7. 用户在发送前删除附件时，调用临时附件删除接口并移除文件。
8. 超过 24 小时未认领的临时附件由启动时或维护任务安全清理。

普通 JSON 请求体大小限制保持不变，媒体上传使用独立限制。音频读取支持 HTTP Range，以便播放器拖动和继续播放。

## 5. 统一编辑器交互

### 5.1 共用组件

帖子、回复和私信共用 `MixedContentComposer`，内部拆分为职责单一的组件：

- 文字输入与 Emoji 选择器。
- 图片选择与缩略图预览。
- `AudioRecorder` 和 `AudioAttachmentPreview`。
- `MedicalMetricCardEditor` 和 `MedicalMetricCardPreview`。
- 统一附件托盘、上传状态和限制提示。

发帖场景在共用编辑器外增加标题、圈子、标签、实名/匿名和病例脱敏确认。回复和私信不显示这些发帖字段。

### 5.2 直接录音

点击麦克风后先请求权限。授权成功后进入清晰的录音状态，显示：

- 正在录音标识。
- 已录时长和 3 分钟上限。
- 停止按钮。

停止后不自动发送，而是显示播放器、时长、删除和重新录制。用户必须试听后自行点击发送。录音使用 Electron Chromium 的 `MediaRecorder`，运行时用 `MediaRecorder.isTypeSupported` 选择当前平台支持的格式。

权限被拒绝、没有可用麦克风或浏览器不支持录音时，不伪装成功；显示简短原因，并保留“上传已有音频文件”入口。

### 5.3 预览和展示

- 图片发送前显示缩略图，可放大查看和删除；发送后可在轻量查看层中浏览原图。
- 音频发送前后都使用相同的播放控件，显示播放/暂停、进度和时长。
- 医学数据卡显示测量时间、1 至 4 个指标、单位、来源和备注，并带“用户手工录入 · 已确认脱敏”标识。
- 每个附件均有明确类型和状态文字，不依赖只有年轻用户才能理解的隐藏图标。
- 私信头部和底部编辑器固定，中间消息区组件内滚动；上传和录音不会改变整页滚动位置。

## 6. 医学数据卡来源扩展

增加只读 `MedicalMetricCardSourcePort`：

- 初版 `ManualMedicalMetricCardSource` 只返回用户当前表单构造的已脱敏数据。
- 未来 B 可提供 `ProviderMedicalMetricCardSource`，返回相同的 `MedicalMetricCard`，但 E 不知道患者仓储、病历表或原始权限模型。
- 来源端口只能返回允许发布的脱敏投影，不能把患者对象透传给社区服务。

手工表单字段包括测量时间、指标和值、单位、数据来源说明、可选备注。必须勾选“不含姓名、患者编号、联系方式等可识别信息”才能添加到编辑器。

## 7. 健康观测趋势图

### 7.1 页面布局

在健康观测工具栏加入紧凑的 `记录列表 / 趋势图`分段切换。默认仍打开记录列表。患者、指标和日期筛选由两个视图共享，切换不整页刷新，也不丢失筛选条件。

趋势视图按纵向排列：

1. 血压：收缩压和舒张压双折线。
2. 血糖：单折线。
3. 心率：单折线。

如果上方指标筛选只选择一项，只显示对应图；选择全部指标时显示三张图。页面不使用四张夸张的大数字仪表盘。

### 7.2 数字摘要

每张趋势图必须在图上方显示：

- 最新值和单位。
- 当前年龄适用的参考区间。
- 当前筛选范围内的记录数。
- 平均值。
- 最低值和最高值。
- 最新值相较第一条记录的绝对变化。

血压分别计算收缩压和舒张压的统计值，并在同一图例中清楚区分。数值根据单位使用稳定的小数位规则，避免出现长浮点数。

鼠标悬停或键盘聚焦数据点时显示指标名称、数值、单位、测量时间、接收时间和数据来源。只有一个数据点时显示点和数字，不虚构趋势线。

### 7.3 年龄参考区间

增加 `ReferenceRangeProvider`，输入指标、患者年龄和观察时间，输出：

- 下限和上限。
- 适用年龄起止。
- 单位。
- 来源名称、版本和更新时间。
- `demo` 或未来 `clinical-configured` 的来源等级。

初版使用本地可配置的演示年龄规则。患者年龄从现有窄化 `HealthPatientSummary` 接口读取，不信任客户端自行传入的年龄。

图中以浅绿色带显示适用区间。区间外的数据点使用形状和文字提示增强辨识，不能只靠颜色。图下注明“演示参考范围，仅供随访查看”以及来源、版本和更新时间。

找不到匹配年龄或单位不一致时，不画参考带并显示“暂无适用参考范围”，不得选择相近年龄、转换单位或自行猜测。

### 7.4 趋势查询

新增独立趋势查询，不复用当前分页表格的一页数据：

- 输入：患者 ID、指标或指标组、开始日期、结束日期。
- 输出：按指标分组的数据点、统计摘要、匹配的参考区间和数据时间范围。
- 单条序列默认最多返回 120 个点。
- 超过上限时使用确定性的时间分桶，保留首点、末点及局部极值，避免把短时峰值简单平均掉。
- 原始记录表仍可分页查看所有记录，不因图表抽样删除数据。

趋势结果使用独立 React Query 查询键。切换视图后保留已有数据，后台更新只替换图表区域。

## 8. API 变化

新增或扩展下列 E 接口：

- `POST /api/v1/social/attachments`：multipart 上传图片或音频。
- `GET /api/v1/social/attachments/:id/content`：受控读取，音频支持 Range。
- `DELETE /api/v1/social/attachments/:id`：仅删除本人未认领的临时附件。
- 现有发帖、回复和私信接口：接受可选 `contentBlocks`。
- 现有帖子详情、评论和私信响应：返回内容块和附件元数据。
- `GET /api/v1/health/observation-trends`：返回筛选范围内的趋势序列、统计和参考区间。

所有富媒体写接口继续携带 `commandId`。重复提交同一个命令不能重复创建业务记录或重复认领附件。

## 9. 错误处理与恢复

- 上传失败：单个附件显示失败和重试，不清空正文或其他已成功附件。
- 文件不合规：在上传前和服务端分别验证，返回大小、格式或时长的具体原因。
- 录音权限失败：关闭录音状态，显示原因和音频上传入口。
- 录音意外中断：如果能生成可播放片段则进入预览，否则明确提示重新录制。
- 业务发送失败：保留全部草稿和附件引用，允许使用同一 `commandId` 重试。
- 媒体读取失败：内容仍显示，附件位置显示“文件暂时无法读取”。
- 医学卡未脱敏确认：禁止添加到附件托盘并定位到确认项。
- 趋势接口失败：保留患者和筛选条件，只在图表区显示重试。
- 趋势无数据：显示当前日期范围无记录，不展示全零折线。
- 参考范围缺失：数据图正常显示，但不画参考带、不判断正常或异常。

结构化日志只记录请求 ID、资源类型、附件类型、字节数、耗时和结果；不记录正文、医学数据卡内容、原始文件名、文件内容或本地绝对路径。

## 10. 缓存与一致性

- 附件上传不触发帖子列表刷新；业务实体创建成功后才精确失效相关列表和详情。
- 发帖成功失效所属圈子、社区首页和“我的帖子”。
- 回复成功失效帖子详情、最新评论排序和相关通知。
- 私信发送成功只更新当前会话、会话摘要和未读计数。
- 趋势图按患者、指标和日期范围缓存；新增观测后只失效该患者相关的记录与趋势查询。
- 所有乐观界面在失败时回滚，数据库和 API 是唯一业务事实来源。

## 11. 可访问性与视觉约束

- 沿用 CareLink 白色、浅灰和青绿色，不增加新的装饰性渐变或大面积统计卡。
- 正文和数字使用当前紧凑字号，不实现全局字体缩放。
- 麦克风、停止、删除、发送等关键按钮同时具有图标、文字或可访问名称。
- 录音和上传状态使用文字与进度，不只依赖颜色或动画。
- 折线图提供键盘可聚焦的数据点和等价文字摘要；参考带、超界点同时使用颜色和形状区分。
- 尊重减少动态效果设置。

## 12. 测试与验收

### 12.1 契约、迁移和服务

- 新迁移可以从现有数据库追加执行，并且旧纯文字数据仍可读取。
- 内容块联合类型和三个创建 DTO 的运行时验证完整。
- 附件所有权、数量、格式、大小、时长、临时状态和重复认领校验。
- 业务创建与附件认领的事务一致性及 `commandId` 幂等。
- 临时附件删除和过期清理不删除已关联文件。
- 医学数据卡指标数量、单位、测量时间和脱敏确认校验。
- 趋势统计、稳定小数格式、日期过滤、多序列血压和确定性抽样。
- 年龄规则匹配、边界年龄、单位不匹配和无适用规则。

### 12.2 API

- 图片、直接录音产物和已有音频的上传、读取及错误响应。
- 音频 Range 请求。
- 发帖、回复、私信携带混合内容后的返回结构。
- 旧客户端不发送 `contentBlocks` 时仍可创建纯文字内容。
- 趋势 API 的数字摘要与数据库原始记录一致。

### 12.3 React

- 三个场景共用编辑器但显示正确的场景字段。
- 图片预览、删除、数量限制和失败重试。
- 麦克风授权、开始、计时、停止、试听、删除、重新录制和上传替代流程。
- Emoji 写入正文。
- 医学数据卡编辑、预览和强制脱敏确认。
- 私信消息区独立滚动且底部编辑器固定。
- 记录/趋势切换、共享筛选、局部加载、空状态和重试。
- 数字摘要、双线血压、参考带、来源标记和无参考范围状态。

### 12.4 整体验证

- 运行仓库现有检查、类型检查、API/Web/Desktop 测试和生产构建。
- 用合成数据手工检查帖子、回复、私信的图片、录音、上传音频和医学数据卡。
- 用多个年龄的合成患者检查参考区间选择和无匹配规则状态。
- 在当前 macOS 桌面应用中检查录音权限和播放；代码保持 Windows 兼容，不在本次打包。

## 13. 完成标准

本功能只有同时满足以下条件才算完成：

- 帖子、回复和私信都能发送、重新加载并展示已确认的混合内容。
- 录音支持开始、停止、试听、删除、重新录制后发送，也支持上传已有音频。
- 医学数据卡不含患者引用，手工脱敏确认有效，未来来源端口已经稳定。
- 趋势图显示完整数字摘要、三类图表、年龄参考带和来源信息。
- 所有新增操作局部刷新，失败不会清空用户草稿。
- 旧纯文字数据和现有 E 功能保持可用。
- 自动检查通过，源代码仍可用于 Windows 和 macOS。
- 没有提交、推送、打包或实现 E 范围之外的业务。
