# E 模块本地实现设计：健康管理与同行社区

日期：2026-09-13

状态：待用户书面确认后进入实现计划
范围：仅 E 负责的 `health`、`community`、`social` 及其公开契约、数据迁移、测试与中英文文案

## 1. 目标与边界

本次把现有只读演示升级为可在本机保存、刷新后仍保留的 E 模块完整功能。实现保留 CareLink 当前桌面外壳和青绿色品牌，不上传 GitHub，不实现 A、B、C、D 的业务。

功能代码必须同时兼容 Windows 和 macOS。安装包、签名、自动更新和发布验证不在本次范围内。

E 的交付范围：

- 健康管理：观测值、健康管理计划、定期评估、提醒任务。
- 同行社区：专科圈子、论坛帖子与回复、点赞、收藏、举报、实名或匿名发布、同行私信、个人社区动态、社区偏好。
- E 的前端页面、API、服务层、SQLite 数据、契约、中英文文案和测试。

明确不做：

- 不实现真实登录、权限中心、总功能开关、平台审计后台、真实通知服务。
- 不实现患者档案编辑、病历、医嘱、问诊或会诊通信。
- 不读取或写入社区之外的患者病历、检查、医嘱或问诊内容。
- 不自动诊断，不根据观测值自动生成治疗方案，不把演示阈值包装成临床判断。
- 不增加字体缩放功能；字号调整由 A 的全局设置负责。

## 2. 交付顺序

采用按业务闭环推进的纵向切片：

1. 健康管理：契约与验证、仓储与服务、API、单列页面、测试。
2. 同行社区：契约与验证、隔离存储、API、单列页面、测试。
3. E 模块整体桌面验证、双语验证、缓存与异常验证。

不采用“先画完全部页面再补后端”的方式。每一个可点击操作都必须连接到同一份本地 API 和 SQLite 数据，不能出现前端一套数字、后端另一套数字。

## 3. 界面方向

设计参数：

- `DESIGN_VARIANCE: 3`
- `MOTION_INTENSITY: 2`
- `VISUAL_DENSITY: 6`

两张页面继续使用现有 CareLink 侧栏和顶栏，但 E 页面内部统一为单列主工作区。健康管理和同行社区仍是两个独立页面，不把临床健康数据和社交内容合并。

视觉约束：

- 沿用当前 CareLink 的白色、浅灰和青绿色，不增加紫色渐变或新的品牌色。
- 页面主标题约 20 至 22 像素，正文约 13 至 14 像素，表格和辅助信息约 11 至 13 像素。
- 删除装饰性英文眉题、宣传口号、超大数字卡和大量悬浮卡片。
- 以搜索、标签页、表格、记录列表、标准表单和侧滑面板为主。
- 主要操作使用带文字的按钮；只在含义明确时使用图标按钮。
- 动画仅用于弹窗、抽屉和保存状态，时长约 150 至 200 毫秒，并尊重减少动态效果设置。
- 所有加载、空数据、保存中、保存成功、字段错误、接口失败和重试状态必须可见。

## 4. 健康管理单列工作区

页面从上到下排列：

1. 紧凑标题栏：`健康管理`、当前数据时间、局部刷新按钮。
2. 患者搜索：输入姓名或患者编号，从 B 的公开患者查询接口获取结果。
3. 已选择患者摘要：只展示公开字段，例如姓名、头像占位、年龄、性别、患者编号、主要诊断和管理状态。
4. 页内标签：`观测记录`、`管理计划`、`健康评估`、`提醒任务`。
5. 单个标签的内容占满一列，不同时出现左右两张业务卡。

### 4.1 观测记录

- 展示血压、血糖和心率的数值、单位、测量时间、接收时间、来源和质量状态。
- 支持日期和指标筛选、分页、局部刷新、查看趋势、查看明细。
- 支持手工录入观测值，严格校验数值、单位和时间。
- 同一患者、来源、外部观测编号的记录做幂等去重。
- 迟到数据保留原测量时间，界面明确显示接收时间，不冒充实时数据。
- 趋势图不显示诊断区间，也不输出正常、异常或治疗建议。

### 4.2 管理计划

- 新建计划草稿，填写标题、目标、复核日期。
- 编辑草稿、启用计划、查看历史版本。
- 使用资源版本防止旧页面覆盖新修改；冲突时提示重新加载。
- 完成度只允许医生手工调整或通过已记录的计划动作更新，不自动推断。

### 4.3 健康评估

- 记录评估时间、摘要、建议、关联计划和下次复核日期。
- 可从评估结果发起一次计划修订，但必须由医生确认。
- 历史评估只读保留，修改建议通过新记录或新计划版本表达。

### 4.4 提醒任务

- 创建、查看、取消和重试提醒任务。
- 展示渠道、计划时间、任务状态、尝试次数和安全错误摘要。
- 没有 A 的通知适配器时，任务保存为 `planned`，界面明确显示“已保存，尚未发送”。
- 真正发送通过注入的 `NotificationProvider`；E 不实现供应商、短信账号或平台通知中心。
- 可重试命令使用幂等键，避免重复创建或重复发送。

## 5. 同行社区单列工作区

社区与健康模块使用完全独立的表、仓储和服务，不订阅临床事件，不保存患者或病历外键。

### 5.1 社区首页

顶部为紧凑页内导航：

- `社区动态`
- `专科圈子`
- `同行私信`
- `我的社区`

社区首页主体是帖子动态列表，不再重复展示一组“功能介绍卡”。每条帖子显示圈子、作者或匿名标识、时间、标题、摘要、标签及评论、点赞、收藏数量。点击进入帖子详情。

### 5.2 我的社区

使用四个正常尺寸的操作入口，不使用大面积统计卡：

- 我的点赞：进入独立列表页。
- 我的收藏：进入独立列表页。
- 我的帖子：进入独立列表页，可继续打开详情。
- 我的消息：打开可关闭的弹窗，显示别人对本人帖子或回复产生的评论、点赞和收藏通知。

“我的消息”不是同行私信，两类数据和界面必须分开。

### 5.3 专科圈子与论坛

- 圈子页分为已加入和可加入列表，支持搜索、加入和退出。
- 进入某个圈子后显示真正的论坛主题列表，而不是社区首页的复制品。
- 论坛支持最新回复、发布时间等排序，支持标签筛选。
- 帖子详情按时间展示正文和多层回复入口。
- 支持发帖、回复、评论、点赞、取消点赞、收藏、取消收藏和举报。
- 发帖可选实名或匿名；涉及病例的内容只能手工输入，并必须勾选脱敏确认。
- 页面固定显示“仅供专业研讨，不能直接作为临床诊疗依据”的提示。
- 举报原因包括虚假医疗观点、广告营销、骚扰和其他；E 只创建举报记录，审核后台留给 A 或后续管理员模块。

### 5.4 同行私信

- 会话列表和当前会话位于一个工作组件内，不触发整页刷新。
- 会话记录区域组件内独立滚动，编辑框固定在组件底部。
- 支持发送文字消息、加载更早消息和显示发送中、已保存、失败重试状态。
- 不复用问诊消息表，不允许附带患者或病历对象引用。

### 5.5 社区关闭

- 个人偏好持久化到 `social_preferences`，不只写浏览器存储。
- 关闭后 E 的社区读取和写入 API 返回稳定的禁用错误，社区消息查询也停止。
- A 的导航隐藏和组织级功能开关只保留适配接口；E 不修改平台权限与设置业务。

## 6. 数据契约与 API

所有接口使用 `/api/v1` 和现有成功/错误信封。新增 `packages/contracts/src/social.ts`；`health.ts` 扩展为输入 DTO、列表 DTO、版本和分页元数据。

### 6.1 健康 API

- `GET /api/v1/health/overview?patientId=...`
- `GET /api/v1/health/observations?patientId=...&metric=...&from=...&to=...&page=...`
- `POST /api/v1/health/observations`
- `GET /api/v1/health/plans?patientId=...`
- `POST /api/v1/health/plans`
- `PATCH /api/v1/health/plans/:id`
- `GET /api/v1/health/plans/:id/versions`

- `GET /api/v1/health/reminders?patientId=...`
- `POST /api/v1/health/reminders`
- `POST /api/v1/health/reminders/:id/cancel`
- `POST /api/v1/health/reminders/:id/retry`

### 6.2 社区 API

- `GET /api/v1/social/feed`

- `DELETE /api/v1/social/posts/:id/likes`
- `POST /api/v1/social/posts/:id/bookmarks`
- `DELETE /api/v1/social/posts/:id/bookmarks`

- `GET /api/v1/social/me/bookmarks`

- `GET /api/v1/social/me/notifications`

## 7. 前后端一致性与数据准备

业务数据只在 SQLite 种子和 API 中维护，React 不再内置帖子、患者读数、计划或私信数组。前端只保留翻译词条和纯展示配置。

本地合成数据目标：

- 8 名现有授权演示患者都具有 E 模块数据。
- 约 30 天的健康观测，覆盖血压、血糖、心率和不同数据来源。
- 8 至 12 个管理计划，包含草稿、启用状态和多个历史版本。
- 12 至 20 条健康评估和 20 条以上提醒任务，覆盖计划中、待处理、失败、取消状态；不预置虚假的真实发送成功。
- 6 个专科圈子、24 条以上帖子、60 条以上评论或回复。
- 30 条以上点赞、20 条以上收藏、20 条以上社区通知。
- 使用现有 3 名合成医生建立 3 个两两私信会话，每个会话 24 至 40 条消息，便于检查组件内滚动。
- 所有人名、患者信息和内容均为明确标注的合成演示数据。

API 测试直接查询数据库并比较响应，保证列表计数、详情、点赞状态、收藏状态和前端展示字段来自同一数据源。

## 8. 局部异步刷新、缓存和加载

前端采用成熟的查询缓存层，优先使用 `@tanstack/react-query`，只在应用组合层增加一次 Provider，不把缓存逻辑散落到每个组件。

查询键按业务资源划分，例如：

- `['health', 'overview', patientId]`
- `['health', 'observations', patientId, filters]`
- `['social', 'feed', filters]`
- `['social', 'post', postId]`
- `['social', 'notifications']`

缓存策略：

- 患者搜索：输入防抖，短期缓存，相同查询不重复请求。
- 健康概览和观测：短缓存，窗口重新聚焦或手工点击时后台更新。
- 圈子、帖子详情和个人列表：中等缓存，写操作后精确失效相关查询。
- 点赞和收藏：乐观更新，失败自动回滚并提示。
- 发帖、评论、计划、评估、提醒：先显示局部提交状态，成功后只刷新相关列表和详情。
- 不使用 `window.location.reload()`，不因为一个请求重新加载整个页面。
- 初次加载显示与最终结构一致的局部骨架；后台刷新保留旧内容并显示轻量刷新标识。
- 错误状态保留用户筛选和表单内容，支持单项重试。

## 9. 日志与可观察性

E 后端记录结构化运行日志，字段包括 `requestId`、`domain`、`action`、`actorId`、资源类型、资源 ID、结果和耗时。

日志不记录患者姓名、观测正文、评估正文、帖子正文、私信正文、手机号、凭证或完整请求体。

业务审计通过可注入的 `AuditWriterPort` 交给 A：

- E 负责在创建计划、修改计划、创建评估、安排或取消提醒、发帖、评论、私信和举报时发出最小审计事件。
- 本地测试使用记录型假实现验证事件内容。
- A 未提供真实实现时不直接写 `audit_events`，也不另建重复的 E 审计系统。

通知发送、设备接入、患者查询和总功能开关同样通过端口连接。端口未配置时返回明确能力状态，不显示假成功。

## 10. 数据库与隔离

- 不修改已经发布的 1 至 6 号迁移。
- 使用新的追加迁移扩展健康版本字段、幂等记录、社区收藏、通知和会话结构。
- `social_*` 表不包含患者、病历、医嘱、问诊或会诊外键。
- 社区仓储不得导入 `patients`、`clinical` 或 `encounters` 的仓储实现。
- 健康服务只通过患者访问/摘要接口校验患者引用，不改患者表。
- 对共享迁移清单和应用组合根的改动只限注册 E 自己的迁移、路由和端口，并在交接说明中单独列出供 A 审查。

## 11. 测试与验收

开发遵循测试先行。每个功能先写失败测试，再实现最少代码使其通过。

后端重点测试：

- 请求验证、患者范围、分页、排序和错误信封。
- 观测去重、迟到数据、计划版本冲突、提醒幂等与失败重试。
- 圈子加入/退出、匿名展示、点赞/收藏幂等、评论和举报。
- 社区禁用后所有通知和互动停止。
- 临床数据变化不会自动产生帖子、评论、私信或社区通知。
- 社区表无临床外键，社区代码无临床仓储依赖。
- 日志和审计事件不泄露正文及患者隐私。

前端重点测试：

- 患者搜索和切换不整页刷新。
- 标签页保留当前患者和筛选条件。
- 计划、评估、提醒保存后只局部更新。
- 我的点赞、收藏、帖子可打开独立页面；我的消息以弹窗展示。
- 私信组件内部滚动，加载更早消息后滚动位置稳定。
- 乐观点赞/收藏失败后正确回滚。
- 中英文文本、键盘操作、焦点恢复、窄窗口和减少动画模式。

最终验证：

- `npm run check`
- E 模块 API 集成测试
- 浏览器端关键路径测试
- Electron macOS 本地运行检查
- Windows 兼容性通过类型检查、Web/API/Desktop 构建和平台无关路径审查验证；本机无法代替真实 Windows 运行验收
- 人工检查所有单列页面、局部加载和失败状态

安装包、签名、自动更新和发行验证不执行，也不作为本次完成条件。

## 12. 本地 Git 安全

- 工作分支：`codex/e-module-local`
- `origin` 拉取地址保留为 GitHub 仓库。
- `origin` 推送地址保持为无效值 `no_push`。
- 不执行 `git push`，不创建远程分支或 PR。
- 实现完成后只向用户提供本地文件、运行方法、测试结果和队友接口交接说明。
