# A → C：会诊临时权限与结束操作交接

这次调整包括会诊权限及问诊界面的真实性和失败处理，不新增双端音视频、录音录像或报告生成算法。

## 对展示流程的影响

- 只有患者当前责任医生能够发起会诊。被邀请者即使能临时查看患者，也不能再创建会诊把权限转给他人或延长有效期。
- 会诊授权到期时间是预约开始后 4 小时，不再等于预约开始时间。因此专家在开始时刻仍可进入，精确到期时失权。
- 已登录且能看到同一患者，不等于参加了每一场会诊。未受邀医生不能直达会诊详情、消息、材料、任务引用，也不能结束会诊。
- 结束操作由发起人或指定审核人执行，普通受邀专家不能结束。
- 结束立即撤销该任务全部临时授权。非发起人不能继续读取该会诊，即使还持有独立的患者权限；发起人保留经患者范围校验的历史查看。
- 删除参与者，或填写 left_at 表示离场后，其任务授权立即失效，不能靠旧 access_grants 继续读患者。离场审核人不能再接受或结束会诊，活动参会列表不再显示其审核角色；发起人的自有权限保持不变。

四小时是本次本地演示的统一配置决定；如需更长会诊，应由 A 修改授权策略和验收，C 不应直接把过期时间设为无限。

## A 已修改的边界

1. platform/consultation-access.ts 统一 consultationMemberSql、consultationAccessUntil、canCompleteConsultation。
2. platform/access.ts 的任务授权要求对应任务仍活动、患者匹配、账号仍为发起人或参与者。
3. encounters/repository.ts 的列表、详情、任务引用、报告引用均使用同一成员约束；创建增加责任医生校验。
4. completeConsultation 把状态更新、临时授权撤销、报告持久保存放在同一数据库事务内。模拟报告写入失败时，任务保持活动且权限保持原状，可修复后重试。
5. 重复完成请求由仍可访问历史的发起人重放时复用已有报告，保留最初完成时间。
6. A 在 app.ts 校验新预约日期，并通过迁移 37 修复既有活动会诊中“授权到期等于开始时间”的旧记录；已撤销授权不恢复。

C 新增服务端功能应调用 repository 已受保护的入口；不要直接查 consultation_messages、consultation_material_uploads、consultation_reports 来绕过授权。共享材料仍需经过 D 的版本及选段检查。

## C 界面已同步的行为

完成会诊后审核人已经失权，界面现已在 POST complete 成功后刷新目录并退出房间，不再请求已撤权的详情。发起人若需看报告，可从历史重新进入。结束按钮仅对活动会诊的发起人/审核人显示，服务端继续独立检查。

后台刷新收到 401/403/404 时会清空当前房间、图片预览和输入，并提示返回列表。完成失败在确认框显示原因、允许重试；发送消息/图片、上传/删除材料的失败也会显示。不会自动创建另一个会诊恢复访问。

排班和改期默认日期使用本机明天，今日容量使用本机今日，改期发送时间按本机时区转 ISO；新会诊默认本机当前时间后一小时，保留 A 的日期校验。

报告仍使用 C 现有的数据汇编方式。这次权限事务修复不代表报告新增正式签署、病历共享正文、双端音视频或真实媒体归档；这些应按演示边界另行验收。

## 回归验证

apps/api/test/consultation-access.test.ts 的 5 项已通过：

1. 开始时刻可进入、开始后 4 小时精确失权。
2. 有同患者访问权但不在会诊的医生不能读取、写消息、上传材料或结束。
3. 临时参会者不能通过创建未来会诊转授权限，移除参与者后原任务授权失效。
4. 普通专家不能结束；强制报告写入失败会回滚状态与撤权；成功完成后临时与永久患者权限都不能让非发起人重新进入结束会诊，发起人可读历史。

5. 参会者设置 left_at 后，即使保留未撤销任务授权或独立患者授权，也不能读会诊、接受或结束；发起人自有权限仍有效。

运行：node --import tsx --test apps/api/test/consultation-access.test.ts。

新增界面测试 consultations-access.test.tsx 共 4 项通过：审核人完成不再读已撤权详情、普通专家无结束按钮、结束失败可重试、后台收权清空已加载讨论。

原 clinical.test.ts 的 10 项病历/医嘱/会诊材料测试也已通过。原 api.test.ts 的手工 CON-SCOPE fixture 需要同时创建参与者，才能表达“有效会诊授权”，不能只插入一行 grant；这是新规则下测试数据的必要补齐。

## 问诊本机预览与文本导出交接

问诊视频页仅提供真实本机摄像头预览：摄像头成功打开后才显示预览状态，拒绝授权会显示错误，停止预览和离开房间会释放设备。页面明确提示患者尚未连接、未录音录像；麦克风按钮禁用。这不是双端 RTC，也不表示音视频归档已完成。

结束问诊仅提交问诊模式和消息数量，不再把视频模式自动当作录音、录像已保存。失败时保留进行中状态并显示错误。消息发送成功后才清空输入，失败保留草稿；发送、结束和导出通过同步请求锁防止重复提交。

导出仅使用服务端已有的保存记录，不再构造保存时间、归档状态或备用记录。没有保存记录时按钮禁用；每次导出前重新请求问诊上下文进行授权，并使用最新服务端记录。权限丢失或查询失败会显示错误，不下载已缓存内容。导出内容明确为文本摘要和聊天文字，未打包图片或音视频文件；音视频标记按真实保存记录展示。

新增 encounters-truthfulness.test.tsx 共 6 项通过：摄像头拒绝与成功预览、发送失败保留输入且防重复、结束失败不伪造媒体保存、无记录禁止导出、导出重新授权且拒绝时无下载、导出使用最新服务端文本。
